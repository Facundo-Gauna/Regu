# Feedback («Contanos») Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pantalla «Contanos» (desde Más y desde cada «Sin confirmar») que manda el mensaje a una función de Vercel, la cual crea un issue en el repo privado `Facundo-Gauna/Regu-feedback`.

**Architecture:** Lógica pura del cliente en `src/vista/feedback.ts` (testeable en Node). Función autocontenida `api/feedback.ts` (sin imports locales, para no depender de cómo Vercel resuelve `.ts`), con su lógica exportada para tests y un `POST` estándar Request/Response. Pantalla Preact `src/app/pantallas/Contanos.tsx` con borrador en `localStorage`. El e2e simula `/api/feedback` en su servidor local; GitHub nunca se toca en pruebas.

**Tech Stack:** TypeScript, Preact, Vite + vite-plugin-pwa (Workbox), `node --test`, arnés e2e propio en Firefox, Vercel Functions (Node).

**Spec:** `docs/superpowers/specs/2026-11-24-feedback-design.md`

## Global Constraints

- Nada sale del dispositivo sin que la persona toque «Enviar»; no hay reintento automático.
- Nunca se envían notas, materias cargadas, estados ni el backup.
- Tipos y etiquetas: `error` «Algo anda mal» · `regla` «Una regla o dato está mal» · `idea` «Una idea» · `otro` «Otra cosa».
- Mensaje: 10–2000 caracteres (tras `trim`). Cuerpo HTTP < 8 KB (8192 bytes). Tope: 5 envíos por IP por hora.
- Variables de entorno: `GITHUB_TOKEN`, `FEEDBACK_REPO`, `ORIGENES_PERMITIDOS` (lista separada por comas).
- Respuestas: 201 creado · 400 inválido · 403 origen · 405 método · 429 tope · 502 GitHub falló · 500 falta configuración. Cuerpo JSON `{ ok: true }` o `{ error: string }`.
- Textos fijos: aviso de contacto «Si querés que te respondamos, dejá tu mail o WhatsApp en el mensaje.» · aviso de privacidad «Lo que escribas, incluido tu contacto si lo dejás, le llega a quien hace Regu.» · éxito «¡Gracias! Lo vamos a leer.» · error «No se pudo enviar. Queda guardado: probá de nuevo cuando tengas internet» · tope «Mandaste varios seguidos. Probá en un rato.» · enlace en «Sin confirmar»: «¿En tu cátedra es distinto? Contanos».
- Español rioplatense en textos de UI, comentarios y commits (como el resto del repo). Los commits terminan con `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
- No se pushea ni se mergea: lo decide Facundo.

## Review Focus

1. Mensaje de puros espacios o con 9 caracteres y espacios alrededor → se rechaza igual en cliente y servidor (tests en Task 1 y Task 2).
2. Mensaje de exactamente 2000 caracteres con acentos y emoji → el cliente lo acepta y el servidor también; los límites son los mismos (test cruzado en Task 2).
3. Doble toque en «Enviar» → un solo envío: el botón queda deshabilitado mientras se envía (e2e en Task 4).
4. Contexto manipulado en la URL (`t=` larguísimo, con `@`, `|`, saltos de línea, Markdown) → se recorta a 200 caracteres y no rompe la tabla ni menciona a nadie (test en Task 2).
5. `#/contanos?d=regla&m=<id inexistente>` → abre sin romperse, con el contexto pero sin materia (test en Task 1).

  - `cerca(texto: string): string` — `` '`'.repeat(Math.max(3, corridaMasLarga + 1)) ``
  - `celda(v: string): string` — colapsa espacios/saltos, recorta a 200, escapa `` \ ` * _ [ ] < > | `` con `\`, inserta U+200B después de cada `@`
  - `armarIssue(e: EnvioValido): { title: string; body: string; labels: string[] }` — título `[<texto del tipo>] <primeros 60 del mensaje en una línea>`; cuerpo: mensaje entre `cerca(...)+'text'` y `cerca(...)`, luego tabla `| Dato | Valor |` con técnico y contexto pasados por `celda`; `labels: [tipo]`
  - `crearLimitador(max: number, ventanaMs: number, ahora?: () => number): (clave: string) => boolean` — `true` = permitido
  - `manejar(req: Request, entorno: Entorno, deps: { fetch: typeof fetch; limitar: (clave: string) => boolean }): Promise<Response>` — orden: método (405) → `Origin` en `ORIGENES_PERMITIDOS` (403) → tope por IP con la primera de `x-forwarded-for`, o `'desconocida'` (429) → largo del cuerpo (400) → JSON y `sitio_web` no vacío ⇒ 201 sin llamar a GitHub → `validarEnvio` (400) → falta `GITHUB_TOKEN`/`FEEDBACK_REPO` (500) → `POST https://api.github.com/repos/${FEEDBACK_REPO}/issues` con `Authorization: Bearer`, `Accept: application/vnd.github+json`, `X-GitHub-Api-Version: 2022-11-28`, `User-Agent: regu-feedback`; no-2xx o excepción ⇒ 502; si no 201. Nunca loguea el mensaje.
  - `POST(req: Request): Promise<Response>` — `manejar(req, process.env, { fetch, limitar })` con un limitador a nivel de módulo `crearLimitador(5, 3_600_000)`
